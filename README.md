# 公路勘察设计交底资料

勘察和设计机构使用交底函、桩号对照及图纸签核记录。
演练资料使用虚构单位、人员与业务文字。资料以 UTF-8 JSON 给出，各文件按收到的顺序保存，正文中引述的名字和词形按原样保留。

## 资料格式

每份资料是记录数组。编号的作用范围是所在资料集，同一业务对象如有不同版本则另列记录。空字符串表示交接文件未填写，空数组表示未列条目。没填写的值无法代替明确的反面事实。

- `data/alignments.json` 保存id、线路、版本、桩号、道路坐标。桩号沿路线向里程增加方向书写。道路坐标为本项目交接里程的米数；断链可使一处有两个桩号。

- `data/landmarks.json` 保存id、名称、线路、版本、道路坐标。道路坐标只在所属线路内可比。正线坐标向东增大。

- `data/segments.json` 保存id、线路、版本、起米、止米。标段区间含两端，交接点为相邻段共有。

- `data/letters.json` 保存id、日期、角色、版本、抬头、内容。外业交底与补录的文本案卷。

- `data/directives.json` 保存id、版本、条文。本项目批准采用的虚构条文，给出调查与设计所需证据。

- `data/drawings.json` 保存id、标段、线路、版本、范围、依赖。范围中的起止使用项目道路坐标，依赖为上游图号列表。

- `data/design_log.json` 保存id、日期、图号、事件、内容。设计回复和送审单留档，内容为经办人原始文字。

- `data/crosswalk.json` 保存线路换版交接表。甲、乙坐标均仅在记录指定的线路内可比。一处可以有多条对应关系。

## 阅读与运行

使用 Python 3.11.2 和标准库，无需安装第三方包。在仓库根目录可列出交接资料，或查看一条原始记录的所有版本。测试核查文本能原样读取和资料之间的关联。

```text
python3 -m corpus
python3 -m corpus letters --id B2
python3 -m unittest discover -s tests -v
```

## 交底定位与出图状态核对（`briefing`）

`briefing` 在原始资料之上做有依据的定位与核对，不修改任何案卷记录。
原句和编号始终保留；分不清的地方输出定位问题与候选范围，而不是替材料选一个位置。

### 命令行

```text
python3 -m briefing                      # 列出可用子命令
python3 -m briefing overview             # 每张图当前状态
python3 -m briefing drawing G1           # 一张图的完整追踪
python3 -m briefing line 正线 --from 300 --to 500
python3 -m briefing facts --id B2        # 某封函拆出的全部事实
python3 -m briefing facts --unlocated    # 只看定位不唯一的事实
python3 -m briefing questions            # 全部定位问题与候选
python3 -m briefing boundaries           # 标段交接点及会签状态
python3 -m briefing boundary 正线 500    # 单个接合点
python3 -m briefing integrity            # 条款解释与资料是否仍一致
```

### 事实怎么读

每条事实对应一个句内小句，字段含义：

- `起坐标` `止坐标`：落在项目道路坐标上的区间；`单点` 表示原句只给出一个位置。
- `书写顺序`：原句写到的地物/桩号顺序；方向词（`以西`、`往回` 等）只用于校验和说明。
- `横向` `单元`：原句写明的横向范围，换算成 `主线北半幅`、`主线南半幅`、`北肩`、`南肩`。
  原句没写横向时列出全部单元并附警示，不等于已覆盖。
- `性质` `覆盖`：`发现`、`未见（有限范围）`、`推测（未测）`、`未覆盖调查`、`定位障碍`、`范围限定`。
  未调查和未测不是排除；`未见` 只在本句写明的范围内成立。
- `排除`：原句明确排除的方向或通道，如“不能代表西侧”“本单未签北肩”。
- `方法`：`初查`、`试坑`、`断面`、`签核`。调查方法和复核方法不能互相顶替。
- `定位问题`：材料无法分辨的定位歧义（断链、同名桥、旧桩号多解、“附近”无范围等）。
- `引用`：`接前函` 这类引用关系，用来区分补录与独立记录。

补录只改变它明确涉及的线路、横向范围与里程；原句没写的部分保持原状。
旧线（甲版）和新线（乙版）各写各的桩号，旧桩号要按跨表或内插换算，换算结果有多个时列为候选。

### 图面状态

`drawing` 输出把原句、条款、设计答复和出图状态串在一起：

- `事实`：每条适用/不适用的事实，含 `条款`、`需求`、`设计答复`、`备注`。
  版次不同的甲/乙事实不套用本图条款，并写明原因。
- `需求`：按批准条款落成的 `调查` 与 `复核` 两项，各自给 `状态`、`证据`、`覆盖`、`未覆盖`。
- `挂起`：`补证`、`待定位`、`待会签` 会阻塞；`提醒` 只提示不阻塞。
  每条挂起都带原句来源、区间和单元。
- `签核覆盖`：只认签核单实际写明的范围与横向；“两端接合已核”只覆盖接合点。
- `送审关系`：送审后到达的勘察记录只把受影响部分转回待确认，其余签核仍有效。
- `历史`：每次送审当时可见的交底与留档，按日期原样列出。
- `边界`：本图两端的接合点状态；一边归不到的边界证据会单列为“待确认归属”。
- `共享构筑物`：交接表只有坐标、没有构筑物编号和几何时，判为不可引用。

### 条款解释

`briefing/directives.py` 把批准条款写成结构化的“调查/复核”要求，并保存条文原文用于核对。
资料里的条文与本文件记录不一致时，`python3 -m briefing integrity` 会报警，避免旧解释套到新条文上。
